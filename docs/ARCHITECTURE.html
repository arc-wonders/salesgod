0. The idea in one screen

The LLM only phrases. What the agent does is decided before the LLM is called, by rules, tables, small learned models with fixed parameters, and business facts. The LLM sees a TurnPlan (objective, {slot} placeholders, must_not_say, ask) and is not allowed to write a number; the validator fills the real values in afterwards and replaces the whole reply with the reviewed template if anything is wrong.

1. Deterministic before the LLM (the guarantee, stage by stage)

Order inside one turn (acie/pipeline.py:207-430): understand -> profile -> explicit requests -> style policy -> emotion row -> (need, move) -> decision plan -> repeat guard -> compile -> LLM wording -> validate. Everything before "LLM wording" is a function of (text, timing, prosody, session, profile, flags), with these exceptions, stated plainly:

stage deterministic? note
rules provider (keywords, lexicons) yes pure Python, acie/providers/rules.py
model provider (trained classifier) yes single-thread predict, ties to the lowest class index (lane/ml)
llm provider (NLU, Qwen3-14B-AWQ) NO (near) temperature 0 and guided JSON (acie/understanding.py:128,130), but a GPU LLM is not bit-exact. It is ON in the voice server (voice/server.py:111 passes nlu for every non-template backend). With ACIE_SIGNAL_PROVIDERS=rules the hearing step is fully deterministic (acie/providers/hub.py:19).
fusion, EMA, policy, tables, moves, ledger, plan yes no random, no hash(), sorted iteration, crc32 only (acie/signals_fusion.py:5, acie/psyche/needs.py:195, acie/memory/hashing.py:25)
LinUCB / XGBoost style policies yes posterior mean, no exploration bonus at decision time (acie/personalization/bandit.py:205)
expression LLM NO temperature 0.3 by default (acie/expression.py:95), 0.0 under ACIE_PSYCHE=1 (:104). It cannot change the plan: llm_allowed=False plans never reach it (acie/pipeline.py:318) and the validator checks the rest
A/B backend choice yes per session sha256 of `salt
playbook generation (frontier model, temp 0.4) NO offline authoring, never in the call path (acie/playbook.py:180); the live picker is deterministic (section 7.4)

What the LLM can and cannot do (acie/compiler.py:121-141, acie/validator.py:160-195): it gets facts only as {slot} placeholders; any digit, rupee sign, number word, invented slot, wrong script, or rule-pack hit fails the sentence and the whole reply becomes the plan's reviewed fallback.

3. The 14-dim HumanState (acie/schemas.py:80-98, acie/signals.py:20)

All values in [0,1]. b = the neutral baseline the EMA decays toward (the field default).

# dim baseline b rule source
1 frustration 0.0 lexicon + repeat + caps/!! + barge-in (estimator.py:227-236)
2 confusion 0.0 lexicon + repeat + short question (estimator.py:216-225)
3 urgency 0.0 lexicon + barge-in + fast speech (estimator.py:238-243)
4 engagement 0.5 minimal reply 0.2 / question or long 0.8 / slow reply (estimator.py:245-253)
5 satisfaction 0.5 0.5 + 0.45*like - 0.5*dislike - 0.25*frustration (dims.py:242)
6 anxiety 0.0 lexicon score (dims.py:249-253)

9 trust 0.5 0.5 + 0.4*trust_up - 0.5*trust_down (dims.py:274-280)

11 cognitive_load 0.0 load lexicon + hesitations + ellipsis + confusion>=0.6 (+0.2) + latency + repeat (dims.py:292-314)

3.1 Lexicon score (acie/state/estimator.py:185-188)

score(hits) = min(1.0, strongest_weight + 0.15 * (number_of_distinct_hits - 1))     0 if no hit

Phrase syntax: x* suffix match, =x whole utterance, masks replace negated phrases first (estimator.py:152-182). If one phrase is inside a longer hit only the longer one counts (:175-181).

3.2 Core four before smoothing (estimator.py:203-258)

repeated      = jaccard(text, previous_customer_turn) >= 0.6
confusion    += lex + 0.3*repeated + 0.2*(text ends "?" and <= 3 tokens)
frustration  += lex + 0.3*repeated + 0.3*(>=2 "!" or (len>8 and UPPERCASE)) + 0.25*barge_in
urgency      += lex + 0.2*barge_in + 0.2*(speech_rate > 3.5 words/s)
engagement    = 0.2 if every content word is a minimal reply; else 0.8 if "?" or >=8 tokens or (>=3 content words and a question word); else 0.5
engagement   -= 0.2 if response_latency_ms > 4000
all clamped to [0,1]

3.3 EMA with a per-dim baseline (estimator.py:396-446)

a = alpha_up   (0.7)  if r > p     else  alpha_down (0.3)          alpha defaults: estimator.py:409
H = b + a*(r - b) + (1 - a)*(p - b)           rounded to 3 decimals   (estimator.py:444-445)

r = raw reading this turn, p = previous smoothed value, b from _BASELINE = the HumanState field default (:393). Rise fast, decay slow; a dim whose neutral value is 0.5 decays to 0.5, not to 0. Worked example: p=0, r=0.8 -> 0.56; next turn r=0 -> 0.392.

3.4 Prosody arousal (only with ACIE_PROSODY=1, estimator.py:434)

baseline = median of the caller's last 8 turns (pitch st, pitch std, loudness dB); a turn > 7.0 st away from the median is dropped from it  (:263-272)
arousal  = 0.45*clip(d_pitch/4,-1,1) + 0.30*clip(var_ratio-1,-1,1) + 0.25*clip(d_loud/6,-1,1);   x min(1, n_baseline/3)         (:298-300)
|d_pitch| > 7 st -> 0 ("probably not the same voice")                                                                            (:294-297)

A calibrated VoiceReading is preferred: arousal = reading.arousal * reading.confidence (:311-319). apply_prosody (:322-353): arousal > 0.25 with negative words -> frustration +0.4*a, urgency +0.15*a, anxiety +(0.4 if worried else 0.2)*a, calmness -0.4*a; with neutral/positive words -> engagement +0.25*a, frustration +0.1*a, excitement +0.5*a, calmness -0.2*a; arousal < -0.25 -> engagement -0.4|a|, calmness +0.4|a|, excitement -0.3|a|.

3.5 Voice calibrator (voice/calibrator.py, per call, numpy, 10-60 ms per turn)

z_k       = (feature_k - centre_k) / spread_k,  centre = median of this caller's baseline turns (max 12, :43)
arousal   = clip( sum_k w_k * tanh(clip(z_k,-4,4)/2) / sum_k w_k / 0.55 , -1, 1 )                       (:215)
conf      = {1 turn: 0.5, 2 turns: 0.75, else 1.0} * min(1, voiced_seconds/0.6)
weights   pitch .32, pitch_var .18, loudness .22, effort .18, rate .10                                 (:40)
spread    defaults 1.5 / 0.6 / 3.0 / 2.5 / 0.9 (:39); fitted on 20 real calls: 0.971 / 0.578 / 1.334 / 1.694 / 0.618 (voice/assets/calib_stats.json)
calibrated once >= 2 baseline turns and >= 1.0 s voiced (:50-51), or 1 turn + a fitted pickup offset; shifts > 7.0 st = another voice (:44)

3.6 Fusion with a trained model or the NLU

  • Trained turn model (ACIE_TURN_MODEL, legacy scorer path): raw = round(0.5*rules + 0.5*model, 3) per dim the model returns (estimator.py:369-372).
  • Provider fusion (acie/signals_fusion.py:123-134): start from the rules' dims; every other provider is blended in turn, v = round((1 - w)*v + w*x, 3) with w = 0.5 (:37); learned_state is the learned providers' own reading.
  • Legacy NLU path (no TurnSignals): 0.5/0.5 per dim the NLU supplies (estimator.py:428-432). The NLU supplies the 4 core dims, and all 14 only with ACIE_NLU_STATE_DIMS=1 (understanding.py:66).

4.2 NLU (acie/understanding.py)

One call per turn: temperature 0, max_tokens 110 (230 with ACIE_NLU_STATE_DIMS=1), guided_json schema (intent enum from the domain guide, buying_signal 0..1, question_topic, objection, the four core dims, gist <= 90 chars), history = last 6 turns, timeout 2.5 s. On any error it returns None and the rules decide alone (:128-137).

5. Layer 3: personalization

5.1 Long-term profile and confidence update (acie/personalization/profile_store.py:52-75)

explicit statement:  value = v, confidence = 1.0, explicit = True  (locks until another explicit statement)
no entry yet:        confidence = lr
same value:          confidence = round(min(1, c + lr*(1 - c)), 3)
different value:     confidence = round(max(0, c - lr), 3); if confidence < 0.3 the value flips and confidence = lr

The policy acts on a stored preference only if explicit or confidence >= 0.6 (policy.py:84,140). Learning rates (learner.py:24-25): LR = 0.1 (pronoun/explicit-marker evidence), LR_WEAK = 0.05 (length/state evidence). Examples: verbosity "low" when <= 4 tokens (LR_WEAK), "high" when >= 25 (LR_WEAK), "med" 8-24 tokens (LR_WEAK/2); formality from aap/ji vs tum/bhai (LR); complexity "high" on jargon (LR_WEAK), "low" on "samajh nahi" (LR); likes/dislikes/topics lists capped at 20 (learner.py:23). Language is updated every turn with lr=0.15 (feedback.py:162); complexity nudged down with lr=0.15 when confusion >= 0.5 and reinforced with lr=0.05 when confusion < 0.2 and frustration < 0.2 (feedback.py:166-170).

5.2 Explicit requests (policy.py:16-102, knobs.py)

Regex tables on normalised, space-padded text; a block pattern cancels a value ("hindi nahi aati"); the last occurrence wins. Keys: language (en/hi/hinglish), verbosity, complexity, regional_variant (delhi, mumbai, lucknow, bihar, south_indian_english), explanation_style, info_density, reassurance. "Hindi mein bhi baat karta hai kya?" is a question about the product, not a switch (pipeline.py:226-228).

Effects (later rules win; "protected" = a learned policy must never override): confused -> complexity low, verbosity high->med, proactivity low; frustrated -> warmth high, verbosity low, proactivity low, formality high (unless low -> med), acknowledge_emotion at most once per 3 turns (ACK_COOLDOWN_TURNS, :83); urgent -> verbosity low, proactivity low; disengaged (and not confused/frustrated) -> verbosity low; anxious or distrustful -> reassurance high + step_by_step; overloaded -> info_density low + complexity low; certain and engaged -> info_density high. Explicit requests then overwrite; a safety-flagged call protects every knob. Language: explicit > explicit profile > mirror the caller; an implicit switch needs 1 turn of >= 4 words or 2 consecutive turns (LANGUAGE_SWITCH_STREAK = 2, :82,240).

5.4 Learned style policies (flags, off)

Shared decision rule (bandit.py:135-159): start from the rule policy's output; for each unprotected knob, among actions with >= min_obs observations, take the argmax of the predicted reward (ties -> earlier action); change the knob only if pred(best) - pred(rule) > margin. Defaults min_obs = 30, margin = 0.1 (bandit.py:191-192; ACIE_STYLE_MIN_OBS, ACIE_STYLE_MARGIN for the XGBoost one, xgb_style.py:34-35). 7 knobs x 3 actions = 21 arms (bandit.py:53-57).

Context x binary, d = 53 = 14*3 + 3 + 4 + 3 + 1 (bandit.py:61): 14 dims bucketed low/mid/high at 1/3, 2/3 (42); language one-hot (3); turn-index bucket {0, 1-2, 3-5, 6+} (4); mean profile-confidence bucket {<0.3, <0.6, >=0.6} (3); bias (1) (bandit.py:70-82).

LinUCB posterior mean (bandit.py:85-103): per arm A = lambda*I + sum x x^T, b = sum r x, theta = A^-1 b, mean(x) = theta . x, lambda = 1, A^-1 kept by Sherman-Morrison: A^-1 <- A^-1 - (A^-1 x)(A^-1 x)^T / (1 + x^T A^-1 x). Rewards clipped to [-1,1]. The optimistic bound mean + alpha*sqrt(x^T A^-1 x) (ACIE_BANDIT_ALPHA 1.0) exists for offline analysis only (:205-208); decisions use the pure mean. State JSON at ACIE_BANDIT_STATE (data/bandit.json), saved every 20 observations, atomic write.

XGBoost style policy (ACIE_POLICY=xgb, xgb_style.py, train_style.py:24-30): one regressor per arm, fixed tree_method=exact, n_estimators=200, max_depth=4, learning_rate=0.1, subsample=1.0, colsample_bytree=1.0, n_jobs=1, random_state=0, objective reg:squarederror. Trained offline from the JSONL log (ACIE_STYLE_LOG); live observe only appends a row. Arms with fewer than --min-obs (30) rows get no model and keep the rule action.

Clarity ladder (moves.py:278-310), start rung = count_move("need:clarity") - 1 (one rung further each time the caller still needs clarity): garbled or nothing said yet: ask_repeat -> offer_stop -> keep_listening; otherwise simplify -> simplify2 -> ask_unclear -> offer_stop -> keep_listening.

Exhaustion (moves.py:244-256): when nothing new is left: nothing_new ("that is all I have") -> keep_listening (ask what else / offer a person or a callback) -> listen (a short cue, reused deterministically). It NEVER hangs up on its own (commit 5655c2f); only the caller's goodbye, no or stop closes (closure/autonomy).

Rotation (moves.py:228-237): start index = how many times that move was used; take the first phrasing in the bank whose sentence is not already in the ledger. No randomness.

Sale gate (moves.py:389-403, profit-free): sells = True only if the need is information, (go_on or sale flag) and engagement >= 0.4, ledger.offers == 0, not refused, decided == "undecided", no payment link yet, the offer slot was already told, and the item is not the offer itself. One gentle offer per call.

SaidLedger (ledger.py): JSON in session.dialog["_said"]: normalised sentences (last 80), whole replies (last 30), intents (count), slots, asks (last 30), moves (count), offers, refused. SIMILAR = 0.6 difflib ratio (:15); repeats checks each sentence of >= 3 words (:72-74); reply_repeats checks the whole reply against earlier whole replies (:76-79).

Repeat guard, always on (pipeline.py:148-173, ACIE_REPEAT_GUARD=0 disables for measuring): for the product_sales domain, when a deterministic (template-only) plan whose intent is in _REPEATABLE (pipeline.py:47) would repeat an earlier whole reply (ratio > 0.6), it is replaced by repeat_move: a caller goodbye/decline -> close; not_understood/clarify/hello/off_topic -> clarity ladder; anything else -> exhaustion (moves.py:445-454).

Other repeat-related thresholds (difflib SequenceMatcher ratio): within-turn duplicate sentence dropped > 0.85 (pipeline.py:289); LLM reply too close to the previous agent reply > 0.7 triggers one regeneration (:381), accepted if <= 0.8 (:388), else only sentences with ratio <= 0.75 vs the previous are kept (:395); echo of the caller dropped > 0.88 after a question, > 0.75 otherwise (:369); restated operator lead dropped > 0.55 (:378); reply cut to 40 words (max_reply_words, :63, keeps the closing question).

Replay result on the 38 recent real calls (docs/REAL_CALLS_FINDINGS.md): agent replies repeating an earlier reply: 37 as logged, 56 on this code with the guard off, 0 with the guard, 0 with ACIE_PSYCHE=1. It measures repetition and determinism, not sales.

7. Layer 4: response determination (acie/decision/, acie/playbook.py, acie/safety.py, acie/context.py)

DecisionEngine.decide -> domain.plan -> TurnPlan (decision/engine.py:120-131). A plan is never prose: objective, facts ({slot} values), decision, must_not_say, ask, fallback templates in en/hi/hinglish, end_call, llm_allowed, lead, rule_packs (schemas.py:156-184).

7.1 Intent classifier (engine.py:36-117)

Weighted keyword hits over normalised text; masks remove negated phrases; priority groups checked in order, highest score in a group wins, ties to the earlier intent; a gated priority intent (affirm/deny) wins only if its score >= the best open intent and its dialog key (pending) exists; weak intents (greetings, thanks) win only if nothing else matched. HybridIntentClassifier (hybrid.py) lets a trained model override only above ACIE_TURN_MODEL_THRESHOLD (0.6) and never over rule-first intents (clarify, human_agent, callback) or a missing gate.

7.2 The call policy: ProductSalesDomain._plan (decision/domains/product_sales.py:762-985)

Fixed gate order, first plan returned wins (the same list is served to the console: acie/trace.py:9-28):

  1. safety (crisis, before the domain) -> 2. compliance (opt-out, never take card/OTP, always admit being an AI, who is calling, number source) :1196 ->
  2. already decided (link sent, no, callback) :1254 -> 4. garbled line: ask to repeat, never sell on it (:798-806; the garbled flag comes from a learned provider, so it needs the llm, model or http provider) ->
  3. consent and close: explicit yes + one confirmation that states the full terms before any link (_confirm_plan :1310, _link_plan :1322) ->
  4. routing: callback with time, human handoff, language switch ->
  5. refusal: at most one soft re-offer after a no (max_reoffers 1, :146; only if frustration < 0.5 and the stage is intro/pitch/close/confirm, :903), then a polite goodbye ->
  6. scripted steps: opening, operator pitch, exact price line, hello, slow-down ->
  7. conversation (_converse :1019): answer what was said first, from product facts and approved answers; a playbook situation adds talking points; llm_allowed=True.

Prices come only through locked slots and the lead line. Negotiation: there is no negotiation state machine in the code. A request for a lower price ("kam nahi kar sakte?") is matched by _NEGOTIATE (:243-249, plus NEGOTIATE_MORE in signals.py) and answered once, from a template, with a price_floor plan ("the price is fixed, no pressure, keep listening", :888-895); the call never ends on it, and pending is set to close. The ledger records quoted: no_lower_price (context.py:57). Declarative constraints (decision/constraints.py:27): min_age, region_allow, exclude_existing_subscriber, price_floor, call_hours (default 9-21, UTC+330 min), dnc, max_reoffers; a violation returns a reviewed template with llm_allowed=False and ends the call.

7.3 Whole-call memory (context.py:79-150)

CallContext folds each turn into promised (payment_link, callback, number removed, team call), quoted (offer_price, no_lower_price), told, questions, objections, decision (accepted/declined/later/undecided), outcome (_AGENT_EVENTS :49, _DECISIONS :66, _OUTCOMES :71); summary() is injected in the prompt as "CALL SO FAR".

7.4 Playbook picker (deterministic, acie/playbook.py:61-107)

Per node: +2.5 if any keyword regex matches; +1.0 if the rule intent is in when.intents; +1.0 if any learned provider's vote is in them; +2.0 if the objection matches; +0.5 if the question topic matches; signal ranges (min_buying, max_buying, min_frustration, min_confusion) must all hold or the node is ruled out (None), and a holding signal-defined node gets +1.5. Best node needs a score >= 2.0; the strict > keeps the first node on a tie; then walk down children while a child scores >= 2.0 (the child replaces its parent). Files: data/voice/playbooks/<tenant>/<product>.json, seed in playbooks/.

9. Layer 8: feedback (acie/feedback.py)

No profit objective: sale outcomes are recorded in profile.outcomes (last 50) and carry weight 0 (SALE_OUTCOME_WEIGHT = 0.0, :66).

Per-turn reward (:128-133, needs turn t+1, so (state, expr) stay pending one turn):

reward = clip( -0.8*d_frustration - 0.6*d_confusion + 0.5*mean(d_engagement, d_satisfaction, d_receptiveness, d_trust) - 0.5*penalty - 0.3*barge_in , -1, 1 )
d_x = x(next turn) - x(this turn);  penalty = 1.0 safe fallback used, 0.4 real validation issue (trim/echo/regenerate are benign), 0 clean;  barge_in = the caller interrupted that reply
weights WEIGHTS (:62); override with ACIE_REWARD_WEIGHTS="frustration=0.9,barge=0.2"

Call-level credit (:64,255-270), summed then clipped to [-1,1], applied to every turn discounted by 0.9^(turns back from the last) (CREDIT_DISCOUNT, :70,284) plus per-turn extras:

+0.5 calm end with every question answered (last frustration < 0.3, confusion < 0.3, nothing unanswered, no pushing after a no)
+0.5 the caller said no/later/stop and the agent never pushed after it
-1.0 opt-out after the agent kept pushing (PUSH_INTENTS: pitch, price, reoffer, recover, confirm_close, price_floor)
-1.0 the caller hung up during or right after a repeated reply
turn extras: -0.5 repeated reply (ratio > 0.6 vs ANY earlier agent reply), -0.5 unanswered question (safe fallback or intent unknown)

Each turn then gets a second policy.observe(...). Safety calls are excluded. observe exists only on the learned style policies, so under the default rule policy nothing is learned from rewards. Validator learning: the last 4 validation results per language are kept in validator_recent_<lang>; >= 2 failures -> complexity "low" (lr 0.2) and prefer_templates=true (lr 0.4); 4 clean in a row -> back to false (:200-210). Outcome label per call (sales_outcome, :103-115): safety > opt_out > accepted/declined/later > no_answer, plus human_agent. Semantic memory (ACIE_MEMORY=1): a compact call summary (decision, objections, last 5 questions, top 5 likes) stored at call end; top-3 similar memories recalled at turn 0 (:290-320, pipeline.py:220). Cosine over 256-d crc32 hashed bag of words + char 3/4-grams (memory/hashing.py:20-40) by default.

12. Latency budget

Per-stage fields written on every agent turn (voice/call.py:533-535): latency_ms.stt, acie_total, tts_first_chunk, first_audio_after_speech_end; pipeline stage marks understand, adapt, decide, first_sentence, total (pipeline.py:211-215,223,236,269). first_audio_after_speech_end is measured from t_end taken when the utterance is handed over (voice/call.py:411), i.e. AFTER the VAD's 700 ms end-of-speech silence (vad_end_silence_ms), so the caller's perceived gap is about 700 ms longer.

Measured on live calls (figures supplied with this task from the call-log summary; the call logs themselves are not in the repo):

stage p50
speech end -> first audio (total) ~1.48 s
STT (Whisper large-v3) ~415 ms
ACIE run_turn (hearing + decision + LLM wording to the last sentence) ~511 ms
TTS first chunk ~289 ms
sum of the three named stages ~1.215 s; the remaining ~0.27 s is hand-over, sentence queueing and audio framing

What is deliberately kept off the critical path: the calibrator, prosody and speaker embedding run in parallel with Whisper (call.py:423); profile load runs in parallel with hearing (pipeline.py:222); the LLM NLU is skipped for short rule-sure turns (hub.py:177); deterministic plans (llm_allowed=False) and the template backend cost no LLM time; sentences stream to TTS as they pass validation when buffer_reply is off; vLLM prefix caching (deploy/voice/salesgod-llm.service:11); a first request after restart is pre-paid by the warm-up (voice/server.py:248-264). Hard budgets: rules 1.0 s, NLU 3.0 s, model 1.0 s, http 2.0 s (section 4), world lookup 2.0 s, expression request timeout 5.0 s.
